# API Contracts

> Moved out of `CLAUDE.md` on 2026-08-29 to keep that file under the size threshold. This is the authoritative source for the full method/path/authorization/behavior table — keep it factually correct the same way `CLAUDE.md` itself must stay correct (update it in the same change as any behavior it describes).

---

The Worker rejects unsafe `/api/*` mutations when Fetch Metadata says `cross-site` or an `Origin` header does not match the request origin. Absent browser headers remain valid for trusted non-browser clients and tests. All non-WebSocket responses receive `nosniff`, frame denial, a minimal CSP, strict-origin referrer policy, disabled camera/microphone/geolocation, and production HTTPS HSTS. API/runtime/auth responses without an explicit cache policy receive `Cache-Control: no-store`; explicit avatar, authorized-file, and static-asset policies are preserved.

When early-access enforcement is on, authenticated but unadmitted API callers receive `403 { code: "early_access_required" }` before endpoint-specific authorization. Desktop bootstrap returns the matching `/early-access` redirect, and presence uses terminal close code `4006`.

| `POST /early-access/unlock` | Public, same-origin browser mutation | Constant-time compare the bounded passcode with `EARLY_ACCESS_PASSWORD`. An authenticated non-revoked user receives an account grant; an anonymous user receives a signed HTTP-only 15-minute pending cookie and is sent through Cloudflare Access. |
| `GET /early-access/complete` | Cloudflare-authenticated return | Accept a valid pending cookie or already-active grant, clear the cookie, and continue to onboarding/validated `return_to`. A pending cookie cannot clear revocation. |

## Validation limits


Keep server validation in `lib/validation.ts` and cover it with unit tests.

- Profile first/last name (`parseProfileInput`, shared by onboarding and account settings): required, NFKC-normalized, whitespace-collapsed, maximum 50 characters each. GitHub handle: optional, trimmed, empty becomes null, maximum 39 characters.

GitHub repository refresh reuses `POST/PUT /api/account/github/device`. A successful production poll atomically replaces scopes for the installations verified by that GitHub identity; failed enumeration preserves existing data. `GET /api/github/callback?setup_action=update` without signed state performs only a redirect to Settings verification. Credential `PUT /api/account/credentials/[provider]` returns `409` while that provider is rollout-disabled; removal remains available.

`GET /api/sessions/[id]/runs?before=<runId>` returns `{ runs, nextCursor }` for a session member, including retained runs of inactive or removed agents. Each page contains at most 20 runs, sorted by `(created_at, id)` descending. An absent cursor starts at the newest run; a cursor from another session yields an empty page. Empty or over-100-character cursor input returns `400`; nonmembership returns concealed `404`. Responses are `no-store`. Existing exact-run artifact/activity authorization continues to apply.

## Personal billing and retained prompts

- `PATCH /api/account/settings`: authenticated caller may set `defaultApiProvider` to null or an enabled connected API provider. An explicit default remains stored after disconnect and requires attention; it never silently falls back.
- `GET /api/account/credentials`: returns caller credential summaries and `defaultApiProvider`. Subscription PUT/PATCH requests are rejected; legacy DELETE remains available.
- `PATCH /api/sessions/[id]/membership`: active member sets only their own `{ autoAgentsEnabled: boolean }`; returns the updated floor and wakes routing.
- Agent create/update accept `usageScope: "private" | "session"`; new agents default private and only their owner may change it. Caller-specific `canUse` and `personalAutoAgentsEnabled` are returned in the floor; teammates' credentials are never exposed.
- `GET /api/sessions/[id]/review/prompts`: members receive 25 retained prompts and `nextCursor`; optional `before`, `engineerId`, and `agentId` filters are bounded to 100 characters. Cursors must belong to this session. Includes contributor facets.
- `GET /api/sessions/[id]/review/prompts/[promptId]`: members receive prompt and 20 run attempts with exact recorded files/checks; `before` pages earlier attempts and must belong to this prompt's queue group and session. Nonmembers and cross-session detail reads receive concealed 404s; invalid cursors receive 400s. Responses are no-store.

GitHub connection responses include `verifiedGitHub` (personal ID, login, verification timestamp). Account responses expose the same nullable identity independently of the editable profile handle. Code run start/retry returns `409 { code: "github_verification_required", error }` when any original prompt author lacks proof; no paid run starts. Floor queue prompts expose a derived `githubVerified` boolean for waiting guidance.

`AgentRun` adds nullable `attribution` (`kind`, ordered public GitHub authors) and `promptedBy` (user ID, current display name, deletion marker). These fields are included in floor snapshots and paginated history without extra per-run queries. They describe original prompters separately from `createdBy`, which remains the dispatcher audit.

Runs and Review contributions expose a nullable validated `commitUrl`. Contributions include immutable `attribution` and current prompt-author deletion markers so History and Review can suppress deleted-user profile links while retaining public Git audit metadata.
