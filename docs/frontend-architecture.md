# Agent Floor Component Structure

> Moved out of `CLAUDE.md` on 2026-08-29 to keep that file under the size threshold. This is the authoritative source for the per-component breakdown of the Agent Floor UI — keep it factually correct the same way `CLAUDE.md` itself must stay correct (update it in the same change as any behavior it describes).

---

- `Workspace.tsx`: orchestration, local layout state, reload-safe conflict attention banner, exact-case Review navigation, and hidden-tab browser-notification coordination.
- `TopBar.tsx`: workspace/review navigation and conflict-attention badge, real member presence, owner invite dialog, settings, sign-out.
- `ObjectiveBar.tsx`: persistent member-editable objective; an owner-only nudge banner opens the same editor once public chat has outpaced the objective's last edit.
- `BriefRail.tsx`: real members, assignments, team chat, and DMs; it does not expose repository rollback actions.
- `AgentFloor.tsx` and `AgentCard.tsx`: empty state, creation dialog, and persisted agent metadata only; agent cards and spotlight do not expose repository rollback actions. A clamped reply sits in the card column above Pause/Stop rather than overlaying them.
- `PromptQueue.tsx`: real queue filtering, ordering, merging, targeting, prompts, “Merge Resolver” run labeling, and authorized per-prompt rollback state/actions. Folded groups (`Conflicted`, `Failed`, `Answered`, `Integrated`, `Cancelled`) carry status-token color on the bar.
- `QueueOrderMenu.tsx`: owner-only ordinary/conflict/PR-feedback automation settings plus the per-device, explicit-permission browser conflict-alert control.
- `FloorDock.tsx`: queue composer, target selection, live teammate drafts, and draft visibility controls.
- `ReviewScreen.tsx`: consumes nullable authoritative review and preview data and provides top-level `Files` / `Prompts` modes plus `Preview` only while `REPOSITORY_PREVIEW_ENABLED=true`. Files retains `Changed` / `All files` browsing. A changed file opens an accessible context menu by right-click, its visible action button, Context Menu key, or Shift+F10. **Change info** shows prompt, agent, and user attribution in a dialog; **Copy path** and **Open on GitHub** provide navigation utilities; owner-only **Remove file changes** confirms before starting the durable base-restore workflow. The middle diff contains code and summary only, without attribution banners. Prompts pages Active or History groups, shows each group's full prompts and exact historical run diff, filters by contributor, and exposes owner-only engineer/agent bulk removal. Preview shows owner-only start/rebuild/stop controls, shared lifecycle facts, stale-fallback notices, and a member-visible sandboxed iframe with reload/new-tab controls; it never grants top-navigation permission. Its compact command bar shows branch-to-base context and diff size without a separate fact grid: **Conflicts** carries amber/red attention, refresh and owner merge-lock controls are icon-only with `HoverTip`, and **Squash merge** carries its ready/waiting/blocked/locked state plus exact blocker tooltip. The owner-only lock is D1-backed and server-enforced. The three column heads share a 56px row so Files, file preview, and Checks line up. Its three columns are drag-resizable like the workspace's (CSS-variable grid columns, 250–560px clamp, stacked under 900px). `selectedConflictCaseId` remains a one-shot signal that opens `ConflictCenterDialog` on the exact case. It keeps an honest empty state when no review exists.
- `ConflictCenterDialog.tsx`: the single popup home for merge conflicts. A rail lists cases open-first with clamped prompt previews; the guided case view shows what happened, every resolver attempt, answer forms only for the session owner/current original prompt authors, waiting text for other members, owner-only retry controls, and a "Resolve manually" step (same owner-or-prompt-author gate, requires `hasSnapshot`) that embeds the per-hunk editor in place rather than stacking a second dialog.
- `ConflictResolver.tsx`: exports `ConflictResolverBody`, the per-hunk manual resolution editor without dialog chrome. Fetches the case's current snapshot on open (same fetch-on-mount/loading/error pattern as `RollbackImpactDialog.tsx`), lists conflicted files down the side, and renders each real hunk as a two-pane ours/theirs diff (`.conflict-panes`, reused from the same CSS the automatic-resolver-era prototype left behind) with a `SegmentedControl` choice; a file with more than one hunk gets a bulk "apply to every section" control. Submission is disabled until every hunk in the snapshot has a choice, and again server-side (the API route recomputes the required set from the same R2 body rather than trusting the client).
- `Rail.tsx`: panel chrome, movement, collapse, expansion, and resize behaviors.

## Guided tour and styling detail


The guided tour's seen-it flags follow the same convention: localStorage `openfloor:tutorial:home:<userId>` and `openfloor:tutorial:floor:<userId>`, owned by `components/GuidedTour.tsx` (ENG-17). The tour auto-opens once per surface on a device with no flag and never returns after Skip or completion; the `<userId>` suffix means a recreated account sees it again, but the dismissal itself stays device-local like the theme. Steps advance only when the user clicks the highlighted element itself (a missing anchor — a control the current role doesn't render — falls back to a Next button), so the tour progresses by doing rather than by reading. `HOME_TOUR` (`components/product/HomeScreen.tsx`) continues past the New session tile into the create dialog it opens, walking Task, Goal, Repository, Candidate branch name, and the AI connection section before ending on the real Create session submit; anchors without a semantic selector (Task, Goal, Candidate branch name) carry a `data-tour` attribute for the tour to target. A user who clicks through without filling task/repository reaches a disabled submit with no click to advance on — Skip is the only escape hatch there, deliberately not a fallback button, since a disabled control isn't a missing one.

### Styling

- Global styles are composed from `app/globals.css` and files under `app/styles/`.
- `tokens.css` is the design-token source.
- Theming: the bare `:root` block in `tokens.css` is Light (crisp near-white); the dark values live twice (under `prefers-color-scheme` guarded against every manual theme, and under `:root[data-theme="dark"]`, deep dark) and must stay identical. Stone is the warm cream manual variant and Charcoal is the warm dark manual variant. `components/ThemeToggle.tsx` cycles System → Light → Stone → Dark → Charcoal, persisting the manual choice in localStorage (`openfloor:theme`); an inline script in `app/layout.tsx` applies it pre-paint. Never hardcode a color a theme must change — the code workbench's inverse surfaces are the deliberate exception (dark in every theme).
- The bare `:root` tokens back the default light theme, overridden by `.shop-shell` (`app/styles/shop.css`) for `/home`, `/onboarding`, `/home/settings`, and the session lobby; `.entry-shell` (`app/styles/layout.css`) for the pre-auth landing and early-access pages; `.app-shell` (`tokens.css`, appended after the four base themes) for `/floor`. `.entry-shell` keeps a brand-specific binary palette but honors the same saved choice: Light/Stone resolve light, Dark/Charcoal resolve dark, and only attribute-free System follows `prefers-color-scheme`; all of its layered card, form, notice, and error colors must come from the matching local token set. `.app-shell`'s light/dark values are ported from `.shop-shell`'s so the floor matches those other shells; it follows the identical `:root[data-theme="dark"] .app-shell, :root[data-theme="charcoal"] .app-shell` plus byte-identical `prefers-color-scheme` resolution pattern. Per-agent tones (`app/styles/components.css`, `--agent-color`) and identity tints (`--who-1/2/3`, `tokens.css`) are retuned inside that same block.
- `components/session/SelectMenu.tsx` is the house dropdown (trigger + styled listbox, combobox keyboard semantics). Do not introduce native `<select>` elements; the OS widget does not match the floor.
- The `legacy-floor-*` filenames describe their origin in the preserved demo UI, not permission to restore demo behavior.
- Reuse genuine visual primitives, but do not reintroduce fixture imports, fake terminals, or simulation logic with old CSS.
- The responsive floor stacks panels and draft lanes on smaller screens.

### Run history and lifecycle clarity

`RunHistoryDialog.tsx`, opened from Agent Floor even when the active roster is empty, pages retained member-visible runs independently of the latest-20 snapshot. It reuses `ActivityTimeline` and `ArtifactToggle` for activity and raw logs. It does not create live-agent controls or show internal session briefs. Queue detail retains both final output and terminal summary; Open agent requires an exact active roster ID.

Persistent-agent creation has Name and Task fields alongside provider/model/billing controls; the legacy role is internally `Engineer`. Idle agents show Idle and disabled Pause/Stop controls. Real publication phases use `runHandoffLabel` plus Spinner; no-change task completion is a separate Completed queue group, including after its run ages out. Failed prompt retry is labeled Retry. Bare `@` opens the existing keyboard-accessible mention suggestions immediately.

`RunAttributionInfo` is shared by Run History and Review contribution details. It shows original prompters, verified profile links and recorded commit links, while distinguishing automated feedback, legacy runs and deleted users. Queue waiting guidance points unverified prompt authors to Settings connection refresh.
